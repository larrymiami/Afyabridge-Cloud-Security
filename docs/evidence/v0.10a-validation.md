## Security governance validation

The reviewer-hardened `Security governance validation` job completed successfully and produced:

```text

Validation modes: {"repository-static":8,"ci-enforced":7,"live-pending":3}
Severity profile: {"critical":6,"high":11,"medium":1}

```

The authoritative `docs/security-control-matrix.md` was reconciled conservatively rather than marking repository controls `Validated` merely because configuration exists. Thirteen posture controls are represented as `Implemented`; the five CSPM controls whose material outcome still depends on later posture/drift/governance work are `In progress`. The posture validator fails if an active posture profile entry points to a matrix control that is still `Planned`, `Accepted`, or `Deferred`.

The count of 15 controls requiring live validation is intentional. v0.10A distinguishes repository/CI validation from effective Google Cloud state rather than converting planned cloud observations into unsupported validation claims.

## Exception-governance binding

The posture profile deliberately reuses the existing `security/exceptions.json` mechanism. The validator requires that exact registry path and the reviewed fields:

- `id`
- `scope`
- `rationale`
- `compensating_controls`
- `owner`
- `approved_by`
- `tracking_url`
- `created_on`
- `expires_on`

The negative suite proves that redirecting posture exceptions to a different registry or deleting the independent approval field is rejected.

## Current boundary

v0.10A validates a version-controlled posture baseline tied to the authoritative security-control matrix, approved ownership/scope, repository evidence paths, control lifecycle, severity and exception governance, explicit validation states, and fail-closed CI controls.

It does **not** prove:

- Cloud Asset Inventory collection or queries;
- Security Command Center enablement or findings;
- effective live organization policies or IAM bindings;
- live network, DNS, KMS, Secret Manager, storage, database, or logging posture;
- an out-of-band Google Cloud drift event and reconciliation; or
- a real cloud finding progressing through remediation and closure.

Those validations require the pending live v0.7 Google Cloud deployment path and later v0.10/v0.11 operational testing.
