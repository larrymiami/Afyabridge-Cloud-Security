## Collector compromise validation

The collector test suite copies the Terraform tree into isolated fixtures, mutates source, and re-runs the real collector. It produced:

```text
Repository posture collector compromise controls validated: 13 scenarios passed.
```

The suite demonstrated detection of changes including:

- service-account key policy weakening;
- service-account key resources;
- primitive IAM roles;
- direct singular and plural public IAM principals;
- Terraform-managed secret payload versions;
- Cloud SQL public IPv4;
- unrestricted Cloud Run ingress;
- removal of the public-invoker guardrail;
- storage public-access-prevention weakening;
- Cloud Armor detachment;
- removal of KMS rotation/destruction defaults;
- project owner metadata removal; and
- centralized organization logging-sink removal.

It also proved that generated `.terraform` cache content is excluded from repository posture facts.

The collector is a focused source-pattern collector over reviewed Terraform contracts, not a general HCL interpreter and not an effective-state engine. Terraform validation, Trivy, OPA, and later live-state collection remain independent layers.

## Initial CI finding retained as evidence

The first v0.10B Security governance execution on Security gates run #118 (`31186626235`) failed inside the new evaluator negative suite after the real repository posture evaluation itself had passed.

The failed test expected removal of a project ownership label to be merge-blocking. The mapped `GOV-C01` control is Medium under the governed severity policy, where `merge_blocking` is false. The evaluator was correct; the test harness was wrong.

The test was corrected to assert the governed blocking decision explicitly rather than weakening or special-casing the evaluator. The final suite now proves both blocking and report-only behavior.

## Current boundary

v0.10B currently validates:

- governed executable repository posture coverage;
- normalized desired-state collection from reviewed Terraform contracts;
- fail-closed posture decisions for Critical/High findings;
- report-only handling where governance explicitly defines a non-blocking severity;
- collector compromise behavior;
- machine-readable and reviewer-readable posture evidence; and
- Terraform drift decision logic with synthetic plans.

It does **not** prove:

- Cloud Asset Inventory collection or queries;
- Security Command Center enablement or findings;
- effective live organization policies or IAM bindings;
- live DNS, network, KMS, Secret Manager, storage, database, logging, or resource-location posture;
- a Terraform plan generated against deployed remote state in drift mode;
- a real out-of-band console/manual change and reconciliation; or
- a real cloud finding progressing through remediation and closure.

Those validations remain dependent on the pending live v0.7 Google Cloud deployment path and later v0.10/v0.11 operational testing.
