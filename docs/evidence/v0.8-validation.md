# v0.8 shift-left security pipeline validation

## Scope

This evidence record covers the repository-level shift-left security controls introduced in v0.8. It does not represent live Google Cloud deployment or runtime security validation.

## v0.8A-v0.8C evidence anchor

Security gates workflow run **#18** (`31166620664`) completed successfully for commit `047555aa78dc12be77e9c093f4bb0538fac54a9e`.

Successful jobs included:

- full-history Gitleaks secret scanning;
- dependency and license review;
- CodeQL for JavaScript/TypeScript;
- CodeQL for GitHub Actions;
- Trivy Terraform misconfiguration scanning;
- Trivy repository package vulnerability scanning;
- web application container build and Trivy image scanning;
- OpenAPI contract and implementation-drift validation; and
- checksum-verified OPA installation, Rego formatting, Rego unit tests, repository fact generation, and repository policy evaluation.

The container gate initially exposed build-context and runtime-image weaknesses. Those failures were remediated by supplying required build configuration, enabling Next.js standalone output, reducing the final runtime image to the production artifact, removing runtime package-manager tooling, upgrading Alpine packages, and retaining a non-root runtime user. The successful #18 run therefore records the remediated state rather than suppressing the findings.

## v0.8D evidence publishing

v0.8D adds:

- a version-controlled security exception registry;
- validation for ownership, independent approval, technical scope, rationale, compensating controls, tracking references, duplicate IDs, dates, expiry, and a maximum 90-day lifetime;
- an always-running evidence job that records all upstream gate results in JSON and Markdown;
- a GitHub job summary; and
- a 30-day workflow artifact containing the evidence outputs.

The final v0.8D workflow run is recorded in `ROADMAP.md` once the reviewed revision completes successfully.

## Enforcement boundary

A successful security workflow proves only that the reviewed repository revision passed the configured static checks. CodeQL publishes static-analysis results to GitHub code scanning; alert-based merge blocking also depends on repository code-scanning and merge-protection configuration. Trivy vulnerability gates ignore unfixed findings and block high/critical findings for which remediation is available. Exceptions do not automatically suppress scanners.

No claim is made here about live Workload Identity Federation, Google Cloud deployment, runtime country isolation, runtime edge controls, dynamic API security, or production incident response.
