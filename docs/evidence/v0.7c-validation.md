# v0.7C validation evidence

## Scope

This evidence records static validation of the v0.7C country-isolated Shared VPC and network-control implementation.

The validated scope includes:

- custom-mode Shared VPC networks;
- regional subnets and VPC Flow Logs;
- Shared VPC host and service-project composition;
- Cloud Router and Cloud NAT;
- restricted Google API routing;
- ingress and egress firewall policy;
- private service access;
- private Google API DNS;
- country-specific Serverless VPC Access connectors;
- a Terraform-generated network provider lockfile.

## Control state

**Implemented and statically validated.**

The Terraform was not applied to a live Google Cloud organization. This evidence does not prove runtime connectivity, effective firewall behavior, API enablement, IAM permissions, DNS propagation, managed-service peering, log delivery, or cross-country isolation in a deployed environment.

## Validated contracts

Static validation confirms that Terraform can parse, initialize, and validate the composed network configuration and its reusable modules.

The configuration declares:

- separate country network inventory entries for Kenya, Ghana, and South Africa;
- unique primary subnet CIDRs across the inventory;
- dedicated private service access ranges;
- dedicated `/28` Serverless VPC Access ranges;
- explicit Shared VPC service-project attachments;
- deny-by-default IPv4 ingress and egress fallbacks;
- narrow health-check and IAP ingress rules;
- restricted Google API routing, DNS, and HTTPS egress;
- same-country internal traffic allowances;
- subnet flow logs, NAT logs, and fallback firewall logs.

## Negative controls represented in code

The implementation does not declare:

- cross-country VPC peering;
- shared country subnets;
- shared Serverless VPC Access connectors;
- direct public SSH or RDP ingress;
- unrestricted public ingress allow rules;
- a general allow-all internet egress rule;
- automatic default subnets;
- implicit service-project discovery.

These are code-level properties only. Runtime absence must be verified after deployment.

## Evidence limitations

The following remain unverified:

- creation of host projects and Shared VPC associations;
- effective routes and firewall evaluation;
- health-check and IAP connectivity;
- blocked public administrative access;
- restricted Google API resolution and reachability;
- private service networking connection establishment;
- Serverless VPC Access connector provisioning and traffic behavior;
- NAT, flow-log, and firewall-log delivery;
- blocked cross-country connectivity;
- post-apply drift state;
- cost, quotas, regional availability, and throughput behavior.

## Result

The v0.7C Terraform network implementation, including its committed provider lockfile, is suitable for review and controlled deployment preparation. It is not yet evidence of a live, secure, or production-ready Google Cloud network.
