# Public edge deployment and rollback

## Purpose

This runbook covers reviewed deployment, validation, promotion, and rollback of the v0.7G regional public edge for Kenya, Ghana, and South Africa.

## Preconditions

Before applying the edge stack, confirm that the target country workload and network stacks are already deployed, the Cloud Run service uses the expected ingress restriction, the Shared VPC network exists, the proxy-only subnet CIDR does not overlap existing ranges, the edge project has the required APIs enabled, and the selected public DNS zone is approved for that country.

Real production hostnames must replace the documentation-only `example.com` values before any live apply. DNS delegation authority must be known before managed-certificate provisioning is attempted.

## Deployment sequence

1. Review the Terraform plan for exactly one country boundary at a time when practical.
2. Confirm the planned edge project, network host project, region, proxy-only subnet, Cloud Run service, DNS zone, hostname, and Cloud Armor preview state.
3. Apply the regional load-balancer foundation and Cloud Armor policy.
4. Publish the DNS authorization CNAME generated by Certificate Manager.
5. Confirm the application A record resolves to the country's reserved edge IP.
6. Wait for the regional managed certificate to become active before treating HTTPS as available.
7. Verify HTTPS on port 443 and the HTTP-to-HTTPS redirect on port 80.
8. Verify the default Cloud Run service URL cannot be used as an unintended public bypass path.
9. Confirm requests reach only the intended country backend and that backend/load-balancer logs are present.
10. Observe Cloud Armor preview logs under representative traffic before promoting WAF or throttling rules to enforcement.

## Cloud Armor promotion

Do not switch a country from preview to enforcement solely because Terraform validates. Review matched rule IDs, request paths, methods, source patterns, response impact, and false-positive candidates. Record any exclusion or sensitivity change with an owner and rationale.

Promote countries independently. A safe Kenya rule set does not prove the same traffic assumptions for Ghana or South Africa.

After enforcement, repeat positive and negative tests and confirm legitimate application flows remain functional.

## Certificate checks

Confirm the DNS authorization CNAME is publicly resolvable and unchanged. Confirm the managed certificate status is active, the expected hostname appears in the certificate, and TLS negotiation rejects protocol versions below the approved minimum.

Certificate issuance and renewal depend on continuing DNS authorization. Removing or changing the authorization record can break future renewal even when the current certificate still appears valid.

## Rollback

For an edge-policy regression, prefer the smallest reversible change:

- return Cloud Armor rules to preview or restore the prior sensitivity/rate limit;
- revert the changed URL map or routing configuration;
- restore the previous DNS record only when DNS itself caused the incident;
- restore the previous certificate/proxy configuration when TLS provisioning or attachment is the fault.

Do not make the Cloud Run service broadly public as a shortcut around an edge outage. Doing so would bypass the security boundary this milestone is intended to create.

## Emergency isolation

If the public edge is actively being abused and normal Cloud Armor containment is insufficient, remove or disable the relevant forwarding path or DNS record through a reviewed emergency change. Preserve logs and configuration evidence before destructive cleanup when possible.

Country isolation remains mandatory during incident response. Do not route one country's production hostname to another country's backend as a temporary recovery mechanism.

## Evidence to capture

Capture the reviewed plan and apply, deployed resource inventory, DNS delegation and resolution, DNS authorization record, certificate status, TLS negotiation, HTTP redirect result, direct-origin denial, country-correct backend response, Cloud Armor preview/enforcement events, throttling test results, backend logs, rollback test, and any residual exceptions.
